## Dify

[仓库](https://github.com/langgenius/dify) · **160,298 Stars** · 核对时间 2026-11-03T07:36:52+00:00

**具体用途：**面向需要搭建 AI 应用的个人和团队，把模型调用、提示词、知识检索、工具调用和条件分支放在可视化工作流中。输入可以是用户问题、上传文档或业务参数，输出可以是带资料依据的回答、结构化结果或应用接口。它适合把多步处理做成可反复运行的应用，并通过运行日志检查哪一步检索或生成出了问题。

**适用场景（示例）：**应用示例：导入产品手册和内部常见问题，先检索对应段落，再让模型生成客服回答；也可以把“识别问题类型→检索资料→整理成指定格式”做成流程，给产品、运营或支持团队使用。适合希望少写后端代码、但愿意配置模型和数据流程的人。

**如何开始：**可先用官方云服务试做一个小型知识问答应用，或按仓库 Docker Compose 指引自部署。配置聊天模型和嵌入模型，导入少量真实文档，调整切分与检索，再把检索节点接到回答节点。用一组已知答案的问题检查引用和遗漏，确认后发布应用或调用 API；自部署需维护数据库、存储及升级配置。

**限制与使用条件：**平台不会自动保证资料正确、检索完整或回答可靠；扫描件质量、切分方式与模型选择都会影响结果。模型 API、托管服务和服务器可能分别收费。Dify Open Source License 基于 Apache 2.0 并含额外条件，涉及多租户服务及前端标识的使用应查看当前许可证，不能按普通 Apache 2.0 项目直接判断。

**具体用途：**面向开发者的有状态 Agent 编排框架，用节点、边和共享状态表达多步任务。开发者可以把模型调用、工具、条件判断和人工介入点组成流程，并利用检查点在中断后恢复执行。它适合需要记住进度、反复调用工具或等待人工确认的任务，产出的是可集成到应用中的工作流逻辑，而非一个开箱即用的聊天网站。

**具体用途：**Nous Research 提供的个人 Agent，支持终端对话、工具使用、会话记忆与技能管理，也可通过网关连接消息平台。其设计包含从使用经验整理技能、搜索历史对话等机制，让重复任务有机会复用已有过程。可配置不同模型提供方，适合把研究、文件整理和脚本操作组织成持续使用的个人助手。

**适用场景（示例）：**应用示例：在受控目录中整理研究材料、运行检查脚本，并把经过人工验证的步骤沉淀为可复用技能；也可通过配置好的消息网关远程查询助手任务。适合希望自行管理模型、工具与个人上下文的使用者。

**如何开始：**按官方安装文档选择 Linux、macOS、WSL2 或原生 Windows 的安装方式，配置模型后先从终端进行只读任务。检查工具范围、历史数据位置与技能内容，再决定是否启用更多执行能力。若需要消息平台，另行配置网关、平台凭据和访问范围；当前知识库仅收录介绍，未安装该 Agent。

**限制与使用条件：**README 中的自我改进指技能、记忆等机制，不能据此理解成模型权重自动训练或任务必然越做越正确。工具执行、消息网关和长期记忆需要自行管理权限与个人数据；模型、托管机器及外部工具可能收费。本批只检查官方资料，未测试长期记忆效果或跨平台稳定性。
