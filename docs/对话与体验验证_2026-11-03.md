## 发现并修复的问题

| 问题 | 修改及验证 |
| --- | --- |
| 连续对话后询问未收录的名称，答案说没有资料，来源卡片却列出上一轮五个语音项目 | 移除无引用时自动附加历史来源的回退逻辑，只返回答案明确引用且有效的资料；真实追问及回归测试均验证空来源。仍允许追问明确引用已更新的历史条目。 |
| “AnythingLLM 桌面版 安装 文档 工作空间 嵌入模型”命中 360 条 | 项目名限定检索，同时保留比较双方及日期/类别条件；同一查询现为 1 条。用途检索继续使用关键词、同义词及相关性排序。 |
| 索引曾去重全部词，重复标题无法发挥权重 | 保留文档内词频，加强名称和用途字段权重；索引升级单独迁移，并验证用户修订及版本记录不变。 |
| 等待时输入框被禁用、不能停止、不知道是否仍在处理 | 显示阶段和经过时间，发送按钮切换为停止；可继续输入下一条草稿。停止后重试能够完成，取消的半条问答不会进入历史。 |
| 失败只有短暂提示；修改后重新发送可能在界面重复显示问题 | 添加对话内错误、重试和放回输入框；保护已有草稿，恢复编辑时移除失败占位。模拟 HTTP 503 和提前结束的数据流后，再接回真实模型验证恢复。 |
| 答案完成后，对话列表刷新失败可能把已完成回答误当作失败 | 分离已完成回答和列表刷新；连接关闭时核对已保存的完整回合，避免丢弃已经完成的结果。 |
| 引用编号、冗长链接、过多卡片、Markdown 符号和手机小字影响阅读 | 显示项目名引用、来源折叠、易读链接标签；安全渲染列表和代码；放大字体和触控区域。详情可把该项目的问题带入输入框。 |
| 刷新后浏览器仍沿用旧版脚本 | 入口和静态资源要求缓存重新校验，并为本次资源增加版本参数。 |

## 验证范围

- 真实多轮：扫描 PDF / Word 知识库选型、限制推荐数量、只选一个并给三步、faster-whisper 与说话人区分、收录日期和发布记录、星数快照、未知项目、Dify 与 AnythingLLM 比较、Ruby 用途。
- 真实浏览器：来源展开/收起、引用详情、项目提问入口、停止生成、输入草稿和 Enter 行为、停止后重试、失败重试、失败后编辑、连接中断、重新加载历史。
- 维护流程：网页新增验收资料、修改用途、查看两版修订、重新提问并引用第二版。仅在测试数据库内操作。
- 布局：390 / 320 像素手机宽度与 1440 像素桌面宽度；对话页面无整页横向溢出，宽表格在自身容器内滚动；另检查手机资料筛选与详情。
- 自动回归：`python -m unittest discover -s tests -v`，17 项全部通过；`node --check web/app.js` 通过。

## 实际边界

仍是本地关键词检索增强问答，没有新增向量模型或自动联网。回答简洁度、硬件条件和日期表达通过提示词约束；生成内容仍可能出错，应以引用原文核对。推荐不等于已经安装、评测或适配本机。故障恢复中的 HTTP 503 与断流由浏览器测试注入；其他问答使用真实后端与模型服务。
